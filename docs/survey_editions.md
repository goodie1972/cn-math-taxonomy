## 四、版本差异的本质（架构判断，未变）

同课标下，版本差异 ≈ 90% 是「同一批知识点在哪一册、哪一章、什么顺序教」的差异；知识点本身高度重合。

→ **题按知识点（topicId）存，版本只决定 topic 的册/章归属与顺序。版本 = 映射层，不是内容层。**
→ 例外：沪教(上海)、部分地方课标，知识点集合本身不同，需另建归属（已建 `shanghai2024`）。

**注册表结构**
```json
{
  "id": "cn_renjiao", "label": "人教版",
  "subjects": {
    "math": { "label": "数学", "topicIds": ["cnm_001", ...], "scope": "一上 + 一下 + ..." }
  }
}
```

## 五、ChinaStudyFree 真题导入（2026-11-02 落地）

### 导入管线（`_scratch/import_csf_v2.py`）

1. **册级对齐**：CSF 册名归一（`数学七年级上册`→`七上`、`必修第一册`→`必修一`）↔ 我方 `chapter` 首段
2. **单元级对齐**：CSF `unit_number` ↔ 我方 `chapter` 里的「第N单元 / 第N章」→ 圈定该单元的候选 topic
3. **子匹配**：单元内用 CSF `knowledge_point` 名与我方 topic 名做相似度匹配；未命中则按 round-robin 均摊到该单元所有 topic（保底覆盖）
4. **题型转换**：`choice`（4 选项，原样保留）→ `choice`；`true_false` → `short`（答案「对/错」+ `accept` 别名）；`fill_blank`/`calculation` → `numeric` 或 `short`；`matching`/`word_order` → `short`
5. **LaTeX → 纯文本**：`\frac{a}{b}`→`a/b`、`\sqrt{x}`→`√(x)`、`\times`→`×`、`\div`→`÷`、`\cdot`→`·`、`\pi`→`π`，去 `$` 与 `\`（引擎无 katex）
6. **过滤**：题干以「同一 / 上题 / 该题 / 同上」开头的依赖上文题直接丢弃（独立看无意义，且校验禁止）
7. **id 从 `_q5` 起**，保留 q1 槽给引擎诊断首题

## 七、诊断引擎与 UI 的版本支持

| 层 | 位置 | 说明 |
|---|---|---|
| 注册表 | `data/editions/registry.json` | 11 个版本，每版本按学科登记 topicIds |
| 引擎 | `diagnose/engine.js` | `editionTargets(registry, versionId, subject, graph)` 按 id 过滤图节点；`versionStatus()` 返回 `{ready, covered, total}` 建库覆盖度 |
| 前端 | `diagnose/app.js` | 「教材版本」下拉位于卡片标题同行最右；列出全部版本；有数据显示「版本名（N 点）」可点，无数据显示「版本名（暂无数据）」灰显 + disabled |
| 引擎灰显判据 | `versionStatus.ready` | 该版本该学科**至少一个知识点已建到题**即点亮；题库补完自动生效，无需改代码 |

**新版本接入 SOP**：在 `registry.json` 的 `versions[]` 加一项 → 填 `subjects.<学科>.topicIds` → 补题 → 自动点亮。
